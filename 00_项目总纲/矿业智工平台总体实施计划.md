# 矿业智工平台总体实施计划

> 项目暂定名称：矿业智工平台  
> 项目定位：面向采矿、选矿、矿山自动化、电气、设备仪表及相关工程专业的在线工具、知识学习、项目协作与企业服务平台  
> 当前阶段核心：先打造国内一流的专业选矿工程在线工具和知识工作台  
> 文档版本：V1.0  
> 编制日期：2026-07-13

---

## 1. 项目愿景

矿业智工平台不是单纯的资料网站，也不是把现有桌面软件原样搬到浏览器，而是建设一个能够真正帮助工程师完成计算、分析、设计、学习、协作和成果输出的专业数字工作台。

平台长期由四个核心能力组成：

1. **专业工程工具**：高频计算、方案设计、设备选型、控制策略、I/O与仪表清单等实用工具。
2. **动态工艺与高级分析**：破碎、磨矿、浮选、浓密、浸出等动态流程、PID仿真、物料平衡、金属平衡和参数拟合。
3. **知识与AI工程助手**：将专业资料、案例、设备、仪表、故障和AI问答与工具深度联动。
4. **项目管理与企业协作**：项目保存、版本管理、团队协作、企业标准库、私有知识库和私有化部署。

第一阶段核心目标：

> 先成为国内专业度高、实用性强、界面优秀的选矿工程在线工具和知识工作台，再逐步扩展到采矿及矿业全专业。

## 2. 实施原则

### 2.1 产品原则

- 先解决工程痛点，再扩充栏目数量。
- 先做选矿核心能力，再扩展采矿、电气、自动化和企业协作。
- 免费功能必须有真实价值，不能只作为空壳引流。
- 付费功能必须明显节省时间、降低错误或形成可交付成果。
- 高风险工程内容必须明确适用范围、假设条件和人工复核要求。
- AI只用于辅助、检查、解释和生成草稿，不替代专业审核与签字。

### 2.2 技术原则

- 桌面版与网页版共用同一套 `mining_core` 计算和仿真核心。
- 不允许网页与桌面分别维护两套公式。
- 多用户仿真必须会话隔离。
- 高级分析、报告生成等耗时任务必须后台执行。
- 权限由后端判定，不能只在前端隐藏按钮。
- 用户数据、企业数据、公共内容必须严格隔离。
- 第一阶段不直接向现场PLC写入控制指令。

### 2.3 设计原则

- 网页美观程度与功能正确性同等重要。
- 不照搬PySide6桌面界面，应重新设计适合浏览器的交互和布局。
- 采用统一设计系统，保证门户、工具、动态流程、项目工作台和管理后台视觉一致。
- 优先支持桌面浏览器，兼顾大屏和平板；手机端以查询、查看和轻量操作为主。
- 重要页面必须具备加载态、空状态、错误态、权限态和无数据态。

- PID仿真
- 设备与仪表知识库
- AI工程助手
- 报告导出
- 管理后台

### 3.2 第二阶段扩展模块

- 浮选、浓密、浸出高级分析
- 自动化方案生成
- 仪表清单、I/O清单和联锁矩阵
- 团队项目与版本管理
- 企业模板和企业知识库
- 采矿工程师工具箱第一批功能

### 3.3 第三阶段扩展模块

- 企业私有化部署
- API与现场数据网关
- OPC UA、Historian和生产数据库接入
- 企业专属AI知识库
- 多专业协作
- 数字孪生与生产分析

### 3.4 第一阶段明确不做

- 不一次性迁移桌面版全部功能。
- 不同时建设大型社区、招聘、商城和设备交易平台。
- 不直接控制PLC或现场设备。
- 不承诺移动端完整工程设计体验。
- 不上线未经审核的工程公式和高风险操作建议。
- 不把未经授权的书籍、标准和厂商手册直接公开下载。

## 4. 产品分层

### 4.1 免费版

主要目标：吸引工程师、建立信任、形成注册和项目创建。

包含：

- 10～20个基础计算工具
- 公开专业文章
- 部分设备和仪表资料
- 一条示范动态工艺路线
- 基础PID教学
- 1～3个云项目
- 每日有限AI额度
- 部分模板下载

### 4.2 专业会员

主要目标：个人工程师付费。

包含：

- 全部专业计算工具
- 完整动态工艺路线
- PID和顺控仿真
- 磨矿、浮选、浓密、浸出高级分析
- 全流程物料与金属平衡
- 参数拟合、灵敏度分析和场景对比
- 自动生成仪表清单、I/O清单和控制策略
- Word、Excel、PDF、PNG报告导出
- 更多云项目和更高AI额度

### 4.3 团队版

主要目标：小型设计院、工程公司、矿山技术部门。

包含：

- 专业会员全部功能
- 团队成员和角色
- 项目共享
- 版本记录
- 审核流程
- 团队模板
- 团队知识库
- 团队AI额度
- 团队报告格式

### 4.4 企业版

主要目标：矿山企业、设计院和自动化公司。

包含：

- 企业组织管理
- 企业私有知识库
- 企业设备、仪表和控制标准库
- 审计日志
- 单点登录
- API接口
- 私有化部署
- 现场数据接入

- 专属技术支持

## 9. 网页视觉设计实施要求

网页设计必须从项目第一天纳入验收，而不是功能完成后再美化。

### 9.1 视觉定位

```text
工业工程软件的专业感
＋
现代SaaS平台的整洁感
＋
数字孪生系统的动态表现
```

### 9.2 设计目标

- 首页有清晰品牌辨识度
- 工具页面高效、准确、无视觉噪音
- 动态流程页面有科技感但不过度炫技
- 项目工作台适合长时间使用
- 会员升级提示自然，不遮挡核心操作
- 深色工程主题为主，报告与内容阅读提供浅色主题
- 所有页面支持高DPI和1366×768以上常见分辨率

### 9.3 首批设计成果

- Logo与品牌色方向
- 首页高保真原型
- 工具中心高保真原型
- 工具详情页高保真原型
- 动态流程页高保真原型
- 项目工作台高保真原型
- 会员中心高保真原型
- 统一组件库
- 图表与流程图规范
- 动效规范

### 9.4 插件与辅助工具策略

可以使用设计、图像、动效和视频类插件辅助：

- 生成首页概念图和视觉素材
- 制作设备与工艺动画原型
- 制作产品介绍视频
- 验证页面转场和微交互
- 快速制作宣传演示

但必须遵守：

- 插件输出不能替代设计系统
- 核心业务界面必须由可维护的React组件实现
- 不把运行时核心功能绑定到不可控插件
- 生成素材必须经过版权和专业性检查
- 插件只作为创意、原型和素材生产工具

## 13. 质量与安全体系

## 15. 主要风险与控制

| 风险 | 控制措施 |
|---|---|
| 范围失控 | 第一版只做选矿核心，严格使用功能清单 |
| 网页与桌面公式分叉 | 强制共用mining_core |
| 页面好看但不好用 | 每页先定义工程任务和核心流程 |
| 工程计算错误 | 公式版本、自动测试、人工复算 |
| AI输出不可靠 | 依据、置信度、风险提示和人工审核 |
| 内容版权问题 | 自主、授权、索引、企业私有内容分开 |
| 多用户仿真串线 | 独立仿真会话和后端隔离 |
| 高级分析拖慢网站 | 后台任务服务 |
| 企业数据泄漏 | 租户隔离、权限、审计和私有部署 |
| 过早投入过大 | MVP、专业版、团队版分阶段投入 |

## 17. 第一年度成功标准

第一年度不以“功能数量最多”为目标，而以形成稳定产品闭环为目标。

必须实现：

```text
用户发现平台
→ 注册
→ 使用工具
→ 创建项目
→ 保存计算
→ 查看动态流程
→ 使用高级功能
→ 生成报告
→ 购买会员
→ 持续复用
```

第一年度核心结果：

- 形成具有辨识度的中文选矿工程平台
- 拥有稳定的共享计算核心
- 拥有一套高质量网页设计系统
- 拥有一批真实工程师用户
- 形成个人会员付费能力
- 形成团队和企业版雏形
- 建立持续更新工具和内容的机制

## 18. 最终执行原则

1. 先做选矿，再扩采矿。
2. 先做共享核心，再做全面网页迁移。
3. 先做完整闭环，再追求大而全。
4. 功能正确与视觉品质同级验收。
5. 每个新功能必须回答：节省什么时间、避免什么错误、形成什么成果。
6. 未经过专业审核的高风险工具不得正式发布。
7. 桌面版继续保留，逐步形成网页版与桌面专业版协同体系。
