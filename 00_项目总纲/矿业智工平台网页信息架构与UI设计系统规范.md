# 2. 设计总体目标

矿业智工平台的网页设计不能照搬现有PySide6桌面界面，也不能套用普通后台管理模板。

平台需要同时体现三种气质：

```text
工业工程软件的专业性
＋
现代SaaS产品的整洁与易用性
＋
数字孪生平台的动态表现力
```

## 2.1 核心体验目标

### 目标一：专业可信

用户进入页面后，应能快速感受到：

- 数据和单位严谨；
- 工具并非普通网页计算器；
- 工艺和设备内容具有行业深度；
- 页面具备工程软件的秩序感；
- 结果、来源、版本和审核状态可追溯。

### 目标二：高效完成任务

用户应能在最短路径内完成：

```text
找到工具
→ 输入参数
→ 得到结果
→ 查看计算过程
→ 保存到项目
→ 导出成果
```

重要操作不得被视觉装饰、动画或复杂层级阻碍。

### 目标三：信息密度高但不拥挤

工程软件需要显示较多参数、表格、趋势和状态。

设计必须做到：

- 信息分组清晰；
- 核心数据优先；
- 细节按需展开；
- 大量参数仍保持对齐；
- 避免大面积空白和无意义装饰；
- 避免桌面软件常见的密集边框与小字体。

### 目标四：形成品牌辨识度

矿业智工平台应建立自己的视觉语言：

- 深蓝黑工程背景；
- 青蓝主色；
- 铜金色行业辅助色；
- 矿物流动线；
- 工业网格；
- 工艺节点与状态灯；
- 专业数据卡片；
- 克制的微光与动态效果。

不得直接照搬其他SaaS产品或通用管理后台。

### 目标五：支持持续扩展

设计系统必须兼容：

- 选矿；
- 采矿；
- 自动化；
- 电气；
- 设备仪表；
- 知识资料；
- AI助手；
- 企业协作；
- 后续新增专业工具。

新增模块时应优先复用既有模板和组件，而不是重新设计一套界面。

# 3. 设计基本原则

## 3.1 任务优先

每个页面首先回答：

1. 用户来到这里要完成什么任务？
2. 页面最重要的操作是什么？
3. 哪些信息必须持续可见？
4. 哪些内容可以按需展开？
5. 出错时用户如何恢复？

## 3.2 数据优先

工程页面中，视觉层级按以下顺序建立：

```text
关键结果
→ 当前状态
→ 输入参数
→ 趋势与关系
→ 计算过程
→ 说明与帮助
```

不得让装饰性图片比关键工程数据更醒目。

## 3.3 渐进式披露

复杂功能采用：

```text
基础信息
→ 高级参数
→ 专业说明
→ 完整技术细节
```

新手可以完成基本操作，专业用户可以继续深入。

## 3.4 统一而非单调

统一：

- 布局；
- 间距；
- 字体；
- 组件；
- 状态；
- 颜色语义。

允许不同模块通过：

- 专业图标；
- 工艺插画；
- 辅助色；
- 页面主视觉；

形成适度差异。

## 3.5 美观不能损害可读性

禁止：

- 大面积高亮渐变；
- 低对比度浅灰文字；
- 高频闪烁；
- 过度发光；
- 玻璃拟态影响文字；
- 图表背景过于复杂；
- 为动画牺牲帧率；
- 为追求“科技感”使用大量无意义线条。

# 4. 目标用户与使用环境

## 4.1 核心用户

### 选矿工程师

主要任务：

- 工艺计算；
- 物料与金属平衡；
- 设备选型；
- 工艺对比；
- 分析试验和生产数据；
- 编制项目成果。

### 自动化工程师

主要任务：

- 查看控制策略；
- 设计PID回路；
- 生成仪表和I/O清单；
- 查看动态工艺；
- 分析故障和趋势；
- 编制自动化方案。

### 设计院工程师

主要任务：

- 创建工程项目；
- 多专业协同；
- 形成设计资料；
- 管理版本；
- 导出报告；
- 复用企业模板。

### 矿山生产技术人员

主要任务：

- 快速计算；
- 生产数据分析；
- 故障诊断；
- 查看工艺与设备资料；
- 对比运行场景。

### 学生与初级工程师

主要任务：

- 学习工艺；
- 理解设备和控制；
- 运行教学仿真；
- 查看计算过程；
- 完成练习。

### 企业管理员

主要任务：

- 管理成员；
- 管理项目；
- 管理企业知识库；
- 管理标准模板；
- 查看审计日志。

## 4.2 主要使用设备

优先级：

1. 桌面浏览器，1920×1080；
2. 桌面浏览器，1366×768；
3. 设计大屏和会议屏；
4. 平板横屏；
5. 手机端轻量查看。

手机端第一阶段不承担：

- 复杂动态流程编辑；
- 大型物料平衡建模；
- 多表格工程设计；
- 高级工艺参数整定。

手机端重点支持：

- 搜索；
- 查看知识；
- 查看项目；
- 简单计算；
- 查看报告；
- AI问答；
- 消息和审批。

# 6. 顶层导航设计

## 6.1 公共门户导航

桌面端顶部导航：

```text
Logo
工具中心
工艺与数字孪生
工程资料库
学习中心
AI工程助手
企业服务
全站搜索
登录/工作台
```

导航要求：

- 页面滚动后保持可见；
- 高度建议64～72px；
- 首页初始状态允许半透明，滚动后变为实色；
- 当前栏目有明确高亮；
- 二级菜单使用宽型下拉面板，不使用狭长层级菜单；
- 重要入口不超过7个；
- “工作台”作为登录后的主要按钮。

## 6.2 工作台导航

工作台采用：

```text
左侧主导航
＋
顶部上下文栏
＋
中央内容区
＋
按需右侧详情栏
```

左侧主导航：

- 工作台；
- 我的项目；
- 工具中心；
- 动态工艺；
- 高级分析；
- 知识库；

- 企业私有页面禁止公开索引。

# 8. 全站搜索架构

## 8.1 搜索范围

全站搜索同时返回：

- 工具；
- 工艺路线；
- 设备；
- 仪表；
- 控制回路；
- 知识文章；
- 故障案例；
- 模板；
- 用户有权限访问的项目；
- AI助手建议入口。

## 8.2 搜索结果分组

```text
工具 5
设备 3
仪表 2
知识 8
项目 1
```

每个结果显示：

- 类型；
- 标题；
- 摘要；
- 相关专业；
- 免费/会员；
- 审核状态；
- 相关工具或项目。

## 8.3 搜索交互

- 顶部导航提供快捷搜索；
- 支持快捷键 `/` 或 `Ctrl+K`；
- 输入时显示即时建议；
- 支持历史搜索；
- 支持拼音与中英文关键词；
- 支持常用缩写，如PID、CIL、P80；
- 无结果时推荐相关分类和AI助手。

# 10. 首页详细设计规范

## 10.1 首页目标

首页应在10秒内让用户明白：

1. 这是矿业工程专业平台；
2. 能做哪些事情；
3. 与普通资料网站有什么不同；
4. 从哪里开始使用；
5. 哪些内容免费；
6. 为什么值得注册或购买会员。

## 10.2 首页首屏

建议布局：

```text
左侧：
主标题
副标题
全站工具搜索
主要行动按钮
次要行动按钮
专业可信标签

右侧：
动态选矿流程概念图
关键数据卡片
设备与物流轻动画
```

推荐主标题方向：

> 面向矿业工程师的专业在线工具与知识工作台

副标题方向：

> 从选矿计算、动态工艺、自动化控制到高级分析与项目成果输出，帮助工程师更快完成工作并减少错误。

主要按钮：

- 开始使用工具；
- 进入工作台。

次要入口：

- 查看动态工艺；
- 了解专业会员。

## 10.3 首页视觉

可使用：

- 深蓝黑渐层；
- 工艺管线；
- 矿物流动粒子；
- 设备轮廓；
- 数据卡片；
- 轻微网格背景。

禁止：

- 复杂三维矿山场景遮挡文字；
- 高频设备动画；
- 大面积视频自动播放；
- 首屏加载大型模型；
- 纯装饰性“科技线”。

## 10.4 首页模块顺序

建议：

1. 首屏主视觉；
2. 热门工具；
3. 四大能力；
4. 动态工艺预览；
5. 工程项目工作台；

# 12. 计算工具详情页设计规范

- 合理步长；
- 上下限；
- 单位；
- 小数位；
- 错误提示。

不得只依赖微小上下箭头。

## 25.3 Select与Combobox

支持：

- 搜索；
- 分组；
- 空状态；
- 键盘操作；
- 最近使用；
- 单位或附加说明。

## 25.4 卡片

类型：

- ToolCard；
- ProjectCard；
- MetricCard；
- KnowledgeCard；
- EquipmentCard；
- MembershipCard；
- AlertCard。

卡片不得全部使用同一视觉。

## 25.5 表格

要求：

- 固定表头；
- 列宽可调整；
- 排序；
- 筛选；
- 冻结列；
- 批量选择；
- 空状态；
- 加载骨架；
- 导出；
- 大数据虚拟滚动。

数值列右对齐。

文本列左对齐。

状态列居中或左对齐保持统一。

## 25.6 Tree

工艺树和项目树应支持：

- 展开折叠；
- 搜索定位；
- 当前节点；
- 状态点；
- 右键菜单；
- 键盘操作；
- 长名称tooltip；
- 虚拟滚动。

## 25.7 Tabs

页签数量超过6个时：

- 使用滚动；
- 或改为侧边导航；
- 或分组。

不允许页签被挤压到难以阅读。

## 25.8 Drawer

右侧详情优先使用Drawer。

宽度：

- 默认420～480px；
- 复杂详情560～640px；
- 支持拖动调整；
- 可固定；
- 可全屏。

## 25.9 Modal

仅用于：

- 确认；
- 权限；
- 关键参数应用；
- 创建或删除；
- 小型任务。

复杂编辑不得放入小弹窗。

## 25.10 Toast与Alert

Toast适合：

- 保存成功；
- 复制成功；
- 任务提交。

Alert适合：

- 数据无效；
- 平衡不闭合；
- 权限不足；
- 安全风险；
- 计算假设。

## 25.11 PermissionGate

统一权限组件显示：

- 功能名称；
- 所需套餐；
- 当前权益；
- 升级入口；
- 返回入口。

## 25.12 EmptyState

不同空状态必须区分：

- 暂无数据；
- 尚未计算；
- 尚未创建项目；
- 无搜索结果；
- 无权限；
- 数据加载失败。

# 27. 动效系统

## 27.1 动效目的

动效只服务于：

- 状态变化；
- 空间关系；
- 操作反馈；
- 工艺因果；
- 页面转场；
- 视觉引导。

## 27.2 动效时长

```text
快速反馈：120～180ms
常规过渡：180～260ms
页面切换：220～320ms
复杂面板：260～420ms
```

## 27.3 工业动画

设备动画：

- 磨机旋转；
- 泵叶轮；
- 搅拌器；
- 皮带；
- 液位；
- 阀门；
- 流动粒子。

必须与仿真状态关联，不做永久装饰动画。

## 27.4 减少动态效果

尊重系统：

```text
prefers-reduced-motion
```

启用后：

- 停止背景粒子；
- 减少页面转场；
- 降低闪烁；
- 保留必要状态反馈。

```text

1024～1279px 小桌面

≥ 1600px     宽屏
```

## 28.2 1366×768

必须重点验收：

- 底部控制条可见；

- 工艺画布充分利用空间；
- 项目工作台允许三栏；
- 表格展示更多列；
- 详情面板可常驻。

## 28.4 平板

- 左侧导航可折叠；
- 右侧详情改为全高抽屉；
- 表格支持横向滚动；
- 工艺流程支持双指缩放；
- 重要按钮触控面积不小于44px。

## 28.5 手机

提供轻量布局：

- 搜索；
- 工具计算；
- 结果查看；
- 项目查看；
- AI问答；
- 报告查看；

复杂动态流程显示只读缩略版或提示使用桌面端。

可用于：

- 首页产品宣传动画；
- 动态工艺演示视频；
- 会员功能介绍；
- 新版本发布视频；
- SVG流程动画原型；
- 网站录屏与宣传片。

该类插件更适合产出：

- HTML动画；
- GSAP动效；
- 标题卡；
- 字幕；
- 视频场景；
- 网站转视频。

不作为生产系统中的核心仿真引擎。

## 33.3 图像生成工具

可用于：

- 品牌概念图；
- 设备视觉探索；
- 专题封面；
- 宣传图；
- 学习插图。

## 33.4 插件使用红线

1. 不将不可维护的插件代码直接作为核心页面。
2. 不依赖插件执行工程计算。
3. 不使用来源不明的素材。
4. 不生成与实际设备原理冲突的动画。
5. 不因视觉效果增加不必要的运行依赖。
6. 不将用户或企业数据发送到未经批准的第三方插件。
7. 插件成果必须归档源文件、版本和用途。

# 40. 设计红线

1. 不允许直接把PySide6界面原样搬到网页。
2. 不允许套用未经定制的通用后台模板作为最终产品。

4. 不允许核心功能完成后才开始美化。
5. 不允许重要页面没有高保真设计就进入全面开发。
6. 不允许页面只设计正常状态。
7. 不允许会员限制只显示一个模糊锁图标。
8. 不允许不同量纲曲线强行放在同一Y轴。
9. 不允许内部英文字段直接显示给用户。
10. 不允许0值显示为无数据。
11. 不允许为科技感使用高频闪烁。
12. 不允许动画影响计算和操作。
13. 不允许企业数据发送到未经批准的设计插件。
14. 不允许生成素材未经专业和版权检查。
15. 不允许1366×768出现关键功能裁切。
16. 不允许移动端承诺无法实现的完整工程能力。
17. 不允许页面没有加载、空、错、权限状态。
18. 不允许表格、图表和动态流程使用完全不同的视觉体系。
19. 不允许设计系统与前端实现分离维护。
20. 不允许未通过专业、功能和视觉三重验收即发布。
