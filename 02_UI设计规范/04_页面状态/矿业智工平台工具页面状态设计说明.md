# 1. 文档目的

本说明用于统一矿业智工平台所有工具页面在不同运行条件下的界面状态、交互行为、文案、组件组合、数据边界和错误恢复逻辑。

工具页面不能只设计“计算成功”一种状态。正式系统必须完整覆盖：

```text
首次进入
→ 输入中
→ 校验中
→ 计算中
→ 计算成功
→ 结果警告
→ 数据不一致
→ 输入错误
→ 计算失败
→ 服务不可用
→ 权限不足
→ 未登录
→ 数据过期
→ 离线
→ 保存中
→ 保存成功
→ 保存失败
→ 导出中
→ 导出完成
→ 无数据
```

本规范重点解决：

1. 用户首次进入页面时看到什么；
2. 用户尚未计算时结果区如何表达；
3. 输入错误与工程范围警告如何区分；
4. 计算中如何防止重复提交；
5. 计算成功后结果如何分层；
6. 数据不一致时是否允许继续保存和导出；
7. 后端服务异常时如何保留用户输入；
8. 会员工具如何展示价值而不是只显示锁；
9. 数据过期、离线和缓存结果如何表达；
10. 保存、导出、复制和项目关联的状态如何统一；
11. 状态变化如何适配1366×768、1920×1080和手机；
12. 状态如何与前端组件、后端错误码和自动测试联动。

# 2. 状态设计原则

## 2.1 状态必须可见

用户必须明确知道：

- 页面现在在做什么；
- 是否已经计算；
- 数据是否有效；
- 当前结果能否用于工程；
- 当前操作是否完成；
- 是否需要用户下一步处理。

不得只依靠按钮禁用或颜色变化暗示状态。

## 2.2 状态必须可恢复

发生错误时必须尽量保留：

- 用户输入；
- 单位选择；
- 高级参数；
- 当前项目；
- 备注；
- 已生成结果；
- 当前滚动位置。

错误发生后不允许无提示清空页面。

## 2.3 错误与警告必须区分

```text
错误 Error
= 无法继续计算或操作

警告 Warning
= 可以继续，但结果需要复核

提示 Info
= 不影响计算，仅提供说明
```

## 2.4 数据状态与页面状态分离

例如：

```text
页面状态：计算成功
数据状态：CAUTION
```

说明：

- 页面操作成功完成；
- 但结果存在工程范围警告。

不能把“计算成功”误等同于“数据完全有效”。

## 2.5 0值必须有效

统一规则：

```text
0 = 有效数值
null = 无数据
undefined = 未提供
NaN = 计算异常
```

页面不允许使用以下错误判断：

```js
if (!value) {
  // 错误：会把0当成无数据
}
```

## 2.6 状态文案必须可执行

错误文案不能只说：

```text
输入错误
```

应说：

```text
固体质量浓度必须位于0%～100%之间，请检查输入数值和单位。
```

## 2.7 工程风险必须明确

对于可能影响工程判断的状态，应明确显示：

- 风险来源；
- 影响范围；
- 是否建议保存；
- 是否允许导出；
- 是否需要专业复核。

# 3. 状态体系总览

工具页面状态分为七类。

## 3.1 页面生命周期状态

```text
INITIAL
EDITING
VALIDATING
CALCULATING
CALCULATED
```

## 3.2 数据有效性状态

```text
NOT_CALCULATED
VALID
CAUTION
INCONSISTENT
INVALID
STALE
MISSING
```

## 3.3 服务状态

```text
ONLINE
DEGRADED
OFFLINE
UNAVAILABLE
TIMEOUT
```

## 3.4 权限状态

```text
GUEST
FREE
PROFESSIONAL
TEAM
ENTERPRISE
NOT_ENTITLED
QUOTA_EXCEEDED
```

## 3.5 保存状态

```text
UNSAVED
SAVING
SAVED
SAVE_FAILED
DIRTY
OFFLINE_DRAFT
```

## 3.6 导出状态

```text
EXPORT_IDLE
EXPORTING
EXPORT_READY
EXPORT_FAILED
EXPORT_NOT_ENTITLED
```

## 3.7 数据来源状态

```text
MANUAL_INPUT
EXAMPLE_DATA
PROJECT_DATA
IMPORTED_DATA
LIVE_DATA
CACHED_DATA
```

这些状态可以组合存在。

示例：

```text
页面状态：CALCULATED
数据有效性：CAUTION
服务状态：ONLINE
保存状态：UNSAVED
数据来源：PROJECT_DATA
```

# 5. 首次进入状态

状态代码：

```text
INITIAL
```

## 5.1 页面表现

首次进入工具页时：

- 工具标题和说明完整显示；
- 输入区显示默认值或空值；
- 结果区显示未计算状态；
- 计算过程区显示说明性占位；
- 保存、复制和导出按钮禁用；
- 公式、适用范围和版本可正常查看。

## 5.2 结果区文案

推荐：

```text
输入参数后开始计算
系统将显示核心结果、计算过程、数据有效性和工程提示。
```

禁止：

```text
暂无数据
```

原因：

“暂无数据”无法告诉用户下一步该做什么。

## 5.3 按钮状态

```text
开始计算：可用
保存到项目：禁用或点击后提示先计算
复制结果：禁用
导出：禁用
```

## 5.4 默认值规则

默认值来源必须明确：

```text
无默认值
教学示例
上次输入
项目参数
企业模板
```

不得把示例值伪装为当前项目值。

---

# 6. 输入编辑状态

状态代码：

```text
EDITING
```

## 6.1 触发条件

用户修改任一输入后进入编辑状态。

## 6.2 页面表现

- 已有结果保留；
- 结果上方显示“输入已修改，结果待重新计算”；
- 保存状态变为`DIRTY`；
- 计算按钮变为“重新计算”；
- 复制和导出可以保留，但必须明确它们对应旧结果；
- 不允许静默自动替换旧结果。

## 6.3 推荐提示

```text
输入参数已发生变化，当前结果仍基于上一次计算。
```

## 6.4 旧结果处理

旧结果可继续显示，但应降低强调并标记：

```text
旧结果
```

如果工具采用实时计算模式，则应进入短暂防抖后重新计算。

# 7. 字段校验状态

字段状态包括：

```text
DEFAULT
FOCUSED
FILLED
WARNING
ERROR
DISABLED
READONLY
```

## 7.1 默认状态

显示：

- 标签；
- 输入框；
- 单位；
- 字段说明；
- 合理范围。

## 7.2 焦点状态

要求：

- 青蓝边框；
- 3px半透明焦点环；
- 不改变布局尺寸；
- 键盘焦点可见。

## 7.3 错误状态

适用于：

- 必填缺失；
- 数值格式错误；
- 超出数学边界；
- 单位不允许；
- 负数非法；
- 百分比超过100%。

表现：

- 红色边框；
- 字段下方错误说明；
- 可选错误图标；
- 提交后滚动至第一个错误字段；
- 屏幕阅读器播报错误。

示例：

```text
矿浆密度必须大于0。
```

## 7.4 警告状态

适用于：

- 超出典型工程范围；
- 数据可能不合理；
- 单位可能选错；
- 值接近边界。

表现：

- 橙色提示；
- 不阻止计算；
- 结果中继续显示诊断；
- 保存和导出时保留警告。

示例：

```text
矿浆密度高于3.5 t/m³，请确认介质和单位。
```

## 7.5 只读状态

适用于：

- 项目锁定参数；
- 企业模板值；
- 上游计算传入值；
- 在线数据值。

必须显示数据来源。

---

# 8. 前端校验状态

状态代码：

```text
VALIDATING
```

前端校验通常时间很短，不必显示全局加载。

应执行：

- 必填检查；
- 数值格式；
- 数学范围；
- 单位兼容；
- 基础字段关系；
- 权限预检查。

如果校验超过300ms，可在计算按钮显示：

```text
校验中…
```

校验失败后：

- 不发送后端请求；
- 显示字段错误；
- 保留全部输入；
- 焦点定位至首个错误。

---

# 9. 计算中状态

状态代码：

```text
CALCULATING
```

## 9.1 页面表现

- 计算按钮显示加载状态；
- 按钮文案“计算中…”；
- 禁止重复提交；
- 输入区可根据工具决定是否暂时锁定；
- 结果区显示骨架或局部加载；
- 不使用全屏遮罩阻断整个页面；
- 公式说明仍可查看。

## 9.2 旧结果存在时

如果已有结果：

- 保留旧结果；
- 顶部显示“正在根据新参数重新计算”；
- 旧结果标记为“上次结果”；
- 新结果返回后替换。

## 9.3 超时提示

超过3秒：

```text
计算仍在进行，请稍候。
```

超过10秒：

```text
计算时间较长，系统仍在处理。你可以继续等待或取消。
```

复杂工具可显示阶段：

```text
正在校验输入
正在执行计算
正在生成诊断
正在整理结果
```

---

# 10. 计算成功状态

状态代码：

```text
CALCULATED
```

数据状态通常为：

```text
VALID
CAUTION
INCONSISTENT
```

## 10.1 页面表现

结果区显示：

1. 一句话结果摘要；
2. 核心结果卡片；
3. 数据有效性；
4. 图表或组成；
5. 计算过程；
6. 警告与诊断；
7. 保存和导出操作。

## 10.2 成功提示

成功提示应简短：

```text
计算成功，结果已生成。
```

不应长期占用大面积绿色区域。

## 10.3 保存状态

计算完成后默认：

```text
UNSAVED
```

显示：

```text
当前结果尚未保存
```

---

# 11. 数据有效状态

状态代码：

```text
VALID
```

## 11.1 条件

- 输入通过校验；
- 无明显工程范围异常；
- 关联数据一致；
- 计算无异常；
- 数据未过期。

## 11.2 表现

- 绿色小状态点；
- 文案“数据有效”；
- 状态代码`VALID`；
- 允许保存；
- 允许导出；
- 允许传递到下游工具。

## 11.3 说明

推荐：

```text
输入参数满足当前工具的计算与一致性要求，结果可用于工程快速复核。
```

不得写：

```text
结果绝对正确
```

---

# 12. 结果需复核状态

状态代码：

```text
CAUTION
```

## 12.1 触发条件

- 输入超出典型工程范围；
- 某可选参数缺失；
- 结果接近边界；
- 使用近似假设；
- 部分数据来源可信度较低；
- 数据存在轻微偏差。

## 12.2 表现

- 橙色状态；
- 结果正常显示；
- 警告列表展开或突出；
- 保存允许；
- 导出允许；
- 导出报告带警告说明。

## 12.3 推荐文案

```text
结果已生成，但存在需要复核的工程提示。
```

## 12.4 操作限制

不应阻止用户：

- 保存；
- 复制；
- 导出；
- 进入下游工具。

但下游工具应继承该状态。

---

# 13. 数据不一致状态

状态代码：

```text
INCONSISTENT
```

## 13.1 触发条件

- 输入之间存在明显物理矛盾；
- 输入密度与理论密度偏差过大；
- 物料平衡闭合误差超限；
- 金属平衡前后不一致；
- 项目上下游数据不匹配。

## 13.2 表现

- 红橙色状态；
- 明确说明不一致来源；
- 核心结果仍可显示；
- 结果卡片不应全部变红；
- 诊断区域必须列出修复建议。

## 13.3 推荐文案

```text
计算已完成，但输入数据之间存在明显不一致，不建议直接用于正式工程成果。
```

## 13.4 保存与导出

允许保存：

```text
保存为待复核记录
```

导出时：

- 明显水印或警告；
- 结果状态写入报告；
- 不允许标记为“已审核”。

## 13.5 下游传递

传递到下游工具前应弹出确认：

```text
当前数据状态为“不一致”。继续使用可能影响后续结果。
```

---

# 14. 数据无效状态

状态代码：

```text
INVALID
```

## 14.1 触发条件

- 计算结果为NaN或无穷；
- 数学模型不适用；
- 输入组合导致无解；
- 后端专业校验失败；
- 单位转换失败；
- 关键参数无效。

## 14.2 表现

- 不显示伪结果；
- 结果值显示“—”；
- 显示具体失败原因；
- 计算过程可显示失败位置；
- 保存可保存为失败记录；
- 导出结果按钮禁用；
- 错误报告可导出。

## 14.3 推荐文案

```text
当前参数组合无法产生有效结果，请根据提示修正输入。
```

---

# 15. 数据缺失状态

状态代码：

```text
MISSING
```

适用于：

- 项目数据字段缺失；
- 导入文件缺少列；
- 在线数据缺少测点；
- 上游工具未提供必要参数。

表现：

- 明确缺失字段；
- 提供补充入口；
- 不把缺失字段自动填0；
- 允许切换为手动输入；
- 保留已有字段。

示例：

```text
缺少矿浆密度。请从项目参数中选择、手动输入或连接在线数据。
```

---

# 16. 数据过期状态

状态代码：

```text
STALE
```

## 16.1 适用场景

- 在线数据超过有效时间；
- 项目引用数据已更新；
- 上游计算版本变化；
- 缓存结果过旧；
- 外部数据源长时间未刷新。

## 16.2 表现

显示：

- 数据时间；
- 有效期；
- 过期时长；
- 刷新入口；
- 是否允许继续计算。

## 16.3 推荐文案

```text
当前数据生成于2小时前，已超过30分钟有效期。
```

## 16.4 处理

根据工具风险分级：

- 低风险：允许继续，标记STALE；
- 中风险：弹出确认；
- 高风险：禁止计算，要求刷新。

---

# 17. 示例数据状态

状态代码：

```text
EXAMPLE_DATA
```

## 17.1 页面表现

顶部或输入区显示：

```text
当前为教学示例数据，不代表实际项目参数。
```

## 17.2 结果状态

即使计算成功，也应保留“示例数据”标签。

## 17.3 保存

允许保存到：

```text
练习项目
```

默认不建议保存到正式项目，除非用户确认。

---

# 18. 项目数据状态

状态代码：

```text
PROJECT_DATA
```

显示：

- 项目名称；
- 数据版本；
- 参数来源；
- 最近更新时间；
- 是否有未保存修改。

输入被修改后：

```text
PROJECT_DATA + DIRTY
```

保存时应创建新计算记录，不静默覆盖已确认记录。

---

# 19. 导入数据状态

状态代码：

```text
IMPORTED_DATA
```

显示：

- 文件名；
- 导入时间；
- 行数；
- 字段映射；
- 无效行；
- 数据质量。

导入成功不等于数据有效。

需区分：

```text
文件导入成功
数据校验通过
```

---

# 20. 在线数据状态

状态代码：

```text
LIVE_DATA
```

必须显示：

- 数据源；
- 测点；
- 时间戳；
- 质量码；
- 更新频率；
- 当前连接状态。

禁止把在线数据的最后值长期显示为当前值而不提示过期。

# 22. 后端校验失败

- 聚焦首个错误；
- 显示request_id。

```json
}
```

# 23. 计算失败状态


- 结果区显示错误状态；
- 不清空输入；
- 保留旧结果；
- 提供重试；
- 显示request_id；
- 可反馈问题。

## 23.2 推荐文案

- 显示Python堆栈；
- 显示数据库错误；

- 自动重复提交多次。

# 42. 响应式状态设计

## 42.1 1920×1080

- 输入、结果、说明三栏；
- 状态说明完整展开；
- 结果与诊断同时可见。

## 42.2 1366×768

- 输入与结果两栏；
- 说明区下移；
- 核心状态首屏可见；
- 计算按钮首屏可见；
- 不出现双重滚动条。

## 42.3 平板

- 单列或双列；
- 警告摘要常驻；
- 详细诊断折叠；
- 保存状态固定在底部操作栏。

## 42.4 手机

顺序：

```text
工具状态
→ 输入
→ 计算
→ 核心结果
→ 数据有效性
→ 警告
→ 计算过程
→ 保存与导出
```

关键错误不得只出现在页面底部。

# 53. 设计红线

1. 不允许只设计成功状态；
2. 不允许错误后清空输入；
3. 不允许0被当成空值；
4. 不允许警告阻止正常计算；
5. 不允许错误与警告使用相同样式；
6. 不允许数据不一致仍标记为VALID；
7. 不允许服务失败只显示Toast；
8. 不允许关键错误只靠颜色；
9. 不允许权限不足只显示锁图标；
10. 不允许离线时伪装在线成功；
11. 不允许缓存结果伪装最新结果；
12. 不允许数据过期不显示时间；
13. 不允许导出报告丢失警告；
14. 不允许保存覆盖已确认记录而无提示；
15. 不允许按钮加载时重复提交；
16. 不允许显示后端堆栈；
17. 不允许没有request_id的服务错误；
18. 不允许状态文案只写“出错了”；

# 56. 结论

工具页面的可信度不仅来自公式正确，也来自状态表达准确。

矿业智工平台必须做到：

```text
用户始终知道当前发生了什么
用户始终知道结果是否可信
用户始终知道下一步应该做什么
错误发生后用户的数据不会丢失
警告和风险不会被隐藏
权限和服务边界不会被伪装
```

本规范将作为后续所有工具页面、专业分析页面和项目计算模块的统一状态基线。
