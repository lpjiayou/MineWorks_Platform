## 二、阶段目标

本阶段将原来分别保存在浏览器中的工具历史升级为统一的数据链：

```text
工具计算结果
→ 统一计算记录
→ 独立保存或关联项目
→ 统一历史检索
→ 结果字段映射
→ 载入其他工具
```


### 4. 项目接口

```text
POST /api/v1/projects
GET  /api/v1/projects
GET  /api/v1/projects/{project_id}
```

### 5. 计算记录接口

```text
POST   /api/v1/calculation-records
GET    /api/v1/calculation-records
GET    /api/v1/calculation-records/{record_id}
PATCH  /api/v1/calculation-records/{record_id}
DELETE /api/v1/calculation-records/{record_id}
```

支持按照工具、项目和关键词查询。

### 6. 结果复用接口

```text
GET /api/v1/calculation-records/{record_id}/reuse?target_tool_id=...
```

接口只返回明确配置过的字段映射，不依赖字段名称猜测。

### 7. 前端保存弹窗

两个正式工具的“保存”操作均已改为统一保存弹窗，支持：

- 保存为独立记录；
- 保存到已有项目；
- 新建项目后立即保存；
- 修改记录标题；
- 填写数据来源和复核备注；
- 显示保存失败原因。

### 8. 统一计算历史页面

新增：

```text
/history
```

支持：

- 搜索记录；
- 按工具筛选；
- 按项目筛选；
- 显示结果摘要；
- 显示数据有效性；
- 将独立记录转入项目；

- 删除记录；

- 将结果载入矿浆密度换算工具。

### 9. 项目工作台

新增：

```text
/projects
```

支持：

- 新建项目；
- 项目编号；
- 项目说明；
- 项目计算记录数量；
- 进入该项目的计算历史。

### 10. 工具结果复用

正式工具支持查询参数：

```text
reuse_record=<calculation_record_id>
```

示例：

```text
/tools/dry-solids-rate?reuse_record=calc_xxx
/tools/slurry-density-conversion?reuse_record=calc_xxx
```

载入后页面明确显示“历史结果复用”，用户必须补充没有映射的字段并重新计算。

## 四、当前字段映射

### 矿浆密度与浓度换算 → 干固体量

```text
矿浆密度 → slurryDensity
固体质量浓度 → solidsMassFraction
```

矿浆体积流量不能从密度换算结果推导，因此保持为空，要求用户补充。

### 干固体量 → 矿浆密度与浓度换算

```text
固体质量浓度 → knownValue
计算模式 → from_mass_concentration
```

固体密度不能从干固体量结果推导，因此要求用户补充；液相密度保留默认值1.0 t/m³。

### 同工具复用

干固体量记录可以重新载入体积流量、矿浆密度和质量浓度。  
矿浆密度记录可以重新载入固体密度、液相密度和质量浓度模式。

## 五、工程边界

1. 复用是数据传递，不代表来源数据已经审核；
2. `CAUTION`、`INVALID`等状态随来源记录显示；
3. 目标工具必须重新执行校验和计算；
4. 不允许通过同名字段自动猜测映射；
5. 单位在映射中显式声明；
6. 复用字段不足时不得自动填0；
7. 项目保存不覆盖原有计算记录，而是创建独立快照。
