# 商业化支付与安全边界 V1.0

## 一、V1.0可以做什么

- 验证套餐页面；
- 验证个人与团队权益；
- 验证功能锁定；
- 验证用量统计与配额；
- 验证订单和订阅数据结构；
- 在本地开发环境模拟支付成功；
- 验证套餐升级后服务端权限刷新。

## 二、V1.0不能用于什么

V1.0不能直接用于公网收费，原因包括：

- 没有真实支付机构；
- 没有支付签名和回调验签；
- 没有订单幂等保护；
- 没有退款和争议处理；
- 没有发票和税务流程；
- 没有自动续费协议；
- 没有财务对账；
- 当前Bearer令牌仍保存在localStorage；
- 当前数据库仍是SQLite。

## 三、正式上线前必须完成

### 身份安全

- HTTPS；
- HttpOnly、Secure、SameSite Cookie或企业OIDC；
- CSRF防护；
- 登录限流；
- 邮箱验证；
- 密码重置；
- MFA；
- 异常登录告警。

### 支付安全

- 支付机构服务端SDK；
- 服务端创建支付单；
- 支付回调验签；
- 幂等键；
- 金额和币种服务端校验；
- 订单状态机；
- 退款状态机；
- 账单和支付流水分离；
- 财务对账和审计。

### 数据基础设施

- PostgreSQL；
- 事务隔离；
- 数据库迁移工具；
- 自动备份；
- 恢复演练；
- 审计日志长期保存；
- 机密信息使用密钥管理服务。

### 法务与运营

- 用户协议；
- 隐私政策；
- 会员服务协议；
- 自动续费说明；
- 退款规则；
- 发票规则；
- 企业采购合同；
- 正式价格审批。

## 四、开发环境开关

```text
MINEWORKS_ALLOW_LOCAL_BILLING_SIMULATION=true
```

公网、预生产和生产环境必须设置为：

```text
MINEWORKS_ALLOW_LOCAL_BILLING_SIMULATION=false
```
