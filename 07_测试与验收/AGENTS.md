# 测试与验收目录规则

本文件适用于 `07_测试与验收`，并补充项目根目录 `AGENTS.md`。

## 目录用途

本目录保存备份说明、截图、终端日志、审计报告、验证报告、迁移报告、部署预演报告、恢复演练报告和双端一致性报告。证据必须能够回答“验证了什么、何时验证、用什么版本和命令、结果是什么”。

第一次 Codex 接管审计报告固定保存到：

```text
02_Codex接管报告\Codex全项目接管审计报告_V1.0.md
```

## 证据规则

1. 报告区分已验证事实、文档声明、推断和待确认项。
2. 记录日期、环境、版本、命令、退出码、成功标志和失败信息。
3. 截图应保留关键路径、版本或成功标志，同时遮蔽用户名、令牌、密码和密钥。
4. 不在报告中复制 `.env`、数据库密码、API/支付密钥、TLS 私钥或真实 `deploy\secrets` 内容。
5. 已签署、已发布或作为基线的证据默认不可覆盖；修订时新建版本并说明替代关系。
6. 不把 `node_modules`、构建产物、虚拟环境或真实数据库复制到本目录充当证据。

## 测试安全

1. 验证脚本默认只读；任何写入、迁移、恢复、清理或部署动作必须有单独任务授权。
2. 数据库测试使用隔离副本或临时数据库，不直接对 `backend\data\mineworks.db` 做破坏性试验。
3. 迁移前记录备份和校验值，迁移后核对表、行数、外键、Alembic revision 和关键业务。
4. 权限验收必须包含未登录、角色不足、项目无权、权益不足和配额不足等负向用例。
5. 计算验收必须覆盖零值、空值、错误值、边界、单位和基准算例。
6. 双端一致性报告必须标明核心、公式和契约版本，并区分实际计算差异与显示精度差异。

## 报告完成条件

- 结论可由证据复核；
- 失败和非阻断技术债未被隐藏；
- 未执行的检查明确标注原因；
- 文件名包含主题和版本；
- 最终报告列出下一步和需要用户确认的动作；
- 未经要求，不执行 Git 提交、数据库迁移或正式部署。
